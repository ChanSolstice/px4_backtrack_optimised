# 返航功能测试文档

## 1. 文档目的

本文档用于验证 `px4_backtrack_optimised` 当前 C++ 版本的返航功能是否符合实现预期，重点覆盖以下行为：

- 飞行周期复位与延时录制
- `CH7` 长按触发返航
- 返航过程中的暂停与恢复
- `CH18` 故障确认与固定点等待返航
- RC 消息丢失触发返航
- 录制点数不足时降级为降落
- 偏离轨迹后的 rejoin
- 返航结束后的降落过渡
- `AUTO.LAND` 优先级让步

本文档面向联调、地面验收、SITL 验证和实飞前检查，不替代单元测试。

## 2. 测试范围

### 2.1 本次覆盖

- 返航主流程
- 触发条件与阈值语义
- 状态机迁移
- 模式切换请求
- setpoint 发布行为
- RC 丢失状态发布
- 调试输出辅助验证

## 7. 测试前准备

### 7.1 环境准备

- 确认节点能够正常启动，无参数缺失报错。
- 确认 `/mavros/state`、`/Odometry_px4`、`/mavros/rc/in` 正常更新。
- 确认 `/mavros/set_mode` 服务可调用。
- 如需可视化验证，开启 `debug_enable_rviz_publish`。
- 如需轨迹离线复盘，开启 `debug_enable_csv_dump`。

### 7.2 记录建议

- 对每条用例记录开始时间、结束时间、环境、参数和实际现象。
- 对失败用例保留 rosbag、终端日志、CSV 与截图。
- 真机测试时先在空旷区域完成 SITL 或地面联调后再执行。

## 8. 判定原则

每条用例必须同时满足以下至少两类证据，才判定通过：

- 状态机状态符合预期
- 模式请求或飞控模式变化符合预期
- setpoint 发布行为符合预期
- 日志明确记录触发源或状态变更
- debug 轨迹或 CSV 能佐证执行路径

禁止仅凭“肉眼看起来像在返航”作为通过依据。
