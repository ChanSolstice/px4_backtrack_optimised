# 弧长驱动返航路径跟随改造方案

## 1. 目的与结论

本方案针对 `5fc74c5` 基线的 Docker SITL 结果，解决名义无扰动长直线返航中的反复 Rejoin 与顿挫。

根因不是 Rejoin 阈值过小，而是当前执行器使用 wall time 推进参考点，并将飞机对时间参考点的纵向落后与真正的横向脱离都视为同一个三维位置误差。SITL 中飞机仍沿直线返航，但因实际速度约 `0.83 m/s`、参考速度约 `1.0 m/s`，累积出 `0.591 m` 纵向落后并误触发 Rejoin。

当前任务的产品需求是“沿录制路径的逆序几何轨迹返航，机头朝向飞行方向”，没有按录制时间到达每个位置的需求。因此主执行逻辑改为弧长驱动的路径跟随：

```text
实际位置
  -> 在返航路径附近局部投影
  -> 得到实际空间进度 s_projection 和横向误差
  -> 在 s_projection 前方选择预瞰目标 s_target
  -> 按轨迹在 s_target 处的位置、速度和 yaw 发布 setpoint
```

Rejoin 仅由横向偏离触发，不再因沿路径方向的速度落后触发。

## 2. 范围和职责边界

### 2.1 当前仓库负责

- 录制点抽稀、逆序与返航输入构造。
- 基于实际 odometry 的在线路径进度管理。
- 预瞰目标选择、横向偏离判定和 Rejoin 交互策略。
- 返航前起始 yaw 对准。
- PX4 setpoint、模式请求、降落和安全状态机。

### 2.2 `trajectory_core` 负责

- 按弧长查询轨迹状态。
- 在指定弧长区间内将三维位置投影到拟合路径。
- 提供投影点弧长、几何位置和距离。
- 修复短路径末端收敛速度剖面与最终报告统计。

投影搜索范围、进度单调性、预瞰距离和 Rejoin 阈值都是任务策略，不放入 `trajectory_core`。轨迹库只执行无状态的几何查询。

### 2.3 本轮不做

- 不通过增大 `rejoin_trigger_dist_m` 掩盖问题。
- 不增加固定 Rejoin 冷却时间。
- 不引入新的路径跟随依赖或通用控制框架。
- 不重写 PX4 位置控制器。
- 不同时重构与返航进度无关的触发、降落和 fallback 状态。
- 首轮不打开加速度前馈；它作为主逻辑通过后的 SITL A/B 验证项。

## 3. `trajectory_core` 最小依赖契约

当前仓库只依赖下列新能力，不访问轨迹库的 pimpl 或公开 `TrajectorySegment` 内部表示：

```cpp
namespace trajectory_core {

struct ProjectionResult {
  bool valid = false;
  double arc_length = 0.0;
  Vec3 position = Vec3::Zero();
  double distance = 0.0;
};

class Trajectory {
public:
  TrajectoryState evaluateByArcLength(double s) const;

  ProjectionResult projectPosition(
      const Vec3& position,
      double s_min,
      double s_max) const;
};

}  // namespace trajectory_core
```

`evaluateByArcLength()` 返回与现有 `evaluate(time)` 相同的位置、速度、可选加速度、yaw 和 yaw rate；`TrajectoryState::t` 填写该弧长在名义速度剖面上对应的时间。

`projectPosition()` 必须把查询限制在 `[s_min, s_max]`，应用层由此避免在自交路径上跳到错误分支。

## 4. 当前仓库设计

### 4.1 补全实际速度输入

`OdomSubscriber` 当前只传递位置、yaw 和时间戳。修改为同时传递 `twist.twist.linear` 速度，并由 `BacktrackUseCase` 保存最新速度。

实际速度只用于：

- Rejoin 退出的速度连续性判定。
- 终点完成判定。
- debug 与 SITL 验收数据。

不在应用层重新估计速度或对 odometry 再做一套滤波。

### 4.2 修复录制点抽稀的末端间距

保留首点和真实末点，但追加末点时必须向前删除与末点距离小于 `min_spacing_m` 的已保留中间点，直到满足间距不变量或仅剩首点。

修复后必须保证：

- 不因覆盖最后一个抽稀点破坏它与前一点的间距。
- 不因末端悬停点簇将路径截断到更早位置。
- 逆序后起点不再存在毫米级相邻点。

### 4.3 `TrajectorySession` 改为空间进度

用以下状态取代 `t_start_walltime_`、`t_progress_`、`progress_frozen_` 和 `frozen_progress_`：

```cpp
double projected_s_;      // 实际位置在路径上的局部投影进度
double target_s_;         // 当前发布目标的进度
bool projection_valid_;
```

每个控制周期：

1. 以上一周期 `projected_s_` 为提示构造局部搜索区间。
2. 调用 `projectPosition(current_position, s_min, s_max)`。
3. 正常跟随中保证 `projected_s_` 不回退。
4. 根据名义路径速度计算预瞰距离：

   ```text
   lookahead_m = clamp(v_profile(projected_s_) * rejoin_lookahead_time_s,
                       lookahead_min_m,
                       lookahead_max_m)
   ```

5. 计算 `target_s_ = min(projected_s_ + lookahead_m, path_length)`。
6. 使用 `evaluateByArcLength(target_s_)` 构造 setpoint。

首轮实现只保留必要参数。`rejoin_lookahead_time_s` 已存在，可复用为正常预瞰时间；`lookahead_min_m` 和 `lookahead_max_m` 先作为代码内部安全边界，只有 SITL 证明需要现场调整时才加入 YAML。

### 4.4 偏离误差改为路径横向距离

正常跟随的偏离误差使用当前位置到局部投影点的距离：

```text
cross_track_error = norm(current_position - projection.position)
```

当前飞机沿路径方向比名义速度慢时，`projected_s_` 自然跟随实际位置，不会累积成 cross-track error。

继续复用现有：

- `rejoin_trigger_dist_m`
- `rejoin_trigger_hold_s`
- `rejoin_success_dist_m`
- `rejoin_success_hold_s`

不为新误差模型再增加一套重复阈值。阶段 D 的受控偏差验证表明，SITL 的正常三维路径误差可长期位于 `0.2–0.35 m`，因此生产配置将 Rejoin 成功走廊设为 `0.4 m`，仍严格小于 `0.5 m` 触发门限。

### 4.5 Rejoin 改为同一路径跟随器的低速模式

保留 `ReturnRejoin` 状态，因为它仍有明确的安全、限速和可观测语义，但删除“冻结时间进度点 + 单独回拉目标”执行方式。

Rejoin 中：

- 允许在正常局部窗口基础上向前扩大投影搜索范围，但不做整条路径全局最近点搜索。
- 目标弧长从投影点开始，预瞰距离随 cross-track error 增大而收缩。
- 参考速度限制为 `rejoin_v_max_m_s`，并随接近路径平滑恢复为路径速度。
- yaw 一直使用目标弧长处的返航轨迹 yaw，不指向横向回拉向量。

Rejoin 退出需要同时满足：

- cross-track error 小于 `rejoin_success_dist_m`。
- 实际速度与恢复后路径目标速度的向量差小于一个内部初始阈值。
- 上述条件持续 `rejoin_success_hold_s`。

若 SITL 证明速度误差需要机型调参，再将它加入 YAML；首轮不预先引入多个速度、预测和冷却参数。

### 4.6 复用 `ReturnPreOffboard` 完成起始 yaw 对准

不新增 `ReturnAlignYaw` 状态。在轨迹生成成功后：

1. 取 `evaluateByArcLength(0).yaw` 作为返航起始切向 yaw。
2. `ReturnPreOffboard` 继续锁定触发时位置，但 hold yaw 更新为返航起始 yaw。
3. 预发送帧数和 `OFFBOARD` 反馈均满足后，还需 yaw 误差进入对准容差才进入 `ReturnActive`。
4. 设置单一对准超时；超时时保持悬停并输出错误，不带着大 yaw 误差开始平移。

### 4.7 终点完成判定

不再使用“轨迹时间结束”作为完成条件。改为同时满足：

- `path_length - projected_s_` 小于末端弧长容差。
- 实际位置到 `goalPosition()` 不大于固定的 `0.2 m` 终点容差。
- 实际水平速度进入低速容差。

这三个条件均来自已有路径进度、终点位置和 odometry 速度，不再增加独立到点系统。终点 `0.2 m` 精度不得再与 Rejoin 安全走廊共用参数，避免为了让 Rejoin 能从正常跟踪误差中退出而同步放宽落点精度。

## 5. 移除被取代的逻辑

弧长主链验证通过后，删除而不保留两套执行器：

- `TrajectorySession::freezeProgress()`
- `TrajectorySession::resumeProgress()`
- `t_start_walltime_`
- `t_progress_`
- `progress_frozen_`
- `frozen_progress_`
- 当前主链未使用的 `RejoinPolicy::findNearestTime()`
- 当前主链未使用的 `RejoinPolicy::computeRejoinTarget()`
- `computeFrozenPointTarget()` 及冻结点相关数据

`WaypointFallbackSession` 仍是独立退化路径，本轮不将它强行并入弧长跟随器。

## 6. 实施阶段与提交边界

### 阶段 A：输入与航点不变量

- 补全 odometry 速度。
- 修复抽稀末端最小间距。
- 增加密集末点和回绕末点单元测试。

### 阶段 B：弧长进度主链

- 接入 `trajectory_core` 弧长查询和局部投影 API。
- 实现单调局部投影和预瞰目标。
- 将 `ReturnActive` setpoint 改为弧长查询。
- 将偏离检测改为 cross-track error。
- 将完成判定改为弧长 + 位置 + 速度。

### 阶段 C：Rejoin 和航向交接

- Rejoin 改为低速、短预瞰的同一路径跟随器。
- 增加速度连续退出条件。
- `ReturnPreOffboard` 完成起始 yaw 对准。
- 删除 wall-time 冻结/恢复和已取代 Rejoin 逻辑。

### 阶段 D：SITL 与可选加速度前馈

- 重跑 3 m 与 8 m 直线。
- 增加 L 型、S 型和自交路径。
- 执行一次受控强制偏离与 Rejoin。
- 主逻辑通过后，对 `enable_output_acc=false/true` 执行 A/B 测试。

每个阶段单独提交，不将公共 API 接入、主执行器替换、Rejoin 策略和 SITL 结果压在同一个提交中。

## 7. 测试与验收

### 7.1 单元测试

- 实际位置沿直线比名义轨迹慢时，cross-track error 接近零且不进入 Rejoin。
- 投影进度在正常跟随中单调不回退。
- 自交路径在局部搜索窗口内不跳分支。
- 实际位置横向离开路径并持续超阈值时进入 Rejoin。
- Rejoin 接近路径但速度差过大时不退出。
- Rejoin 退出前后 target position、velocity 和 yaw 连续。
- 到达路径末端但位置或速度未满足时不进入 `LandingHover`。
- 起始 yaw 未对准时保持 `ReturnPreOffboard`。

### 7.2 SITL 通过标准

- 8 m 名义无扰动直线 Rejoin 次数为 `0`。
- 名义跟随中 cross-track error 不因速度落后持续增长。
- 3 m 短路径存在明确的加速和减速过程，不得全程锁定在约 `0.07 m/s`。
- 强制横向偏离只触发一次 Rejoin，退出后 3 s 内不得重新触发。
- Rejoin 退出前后参考速度向量跳变不大于 `0.3 m/s`。
- 开始水平返航前，实际 yaw 对起始路径 yaw 误差不大于 `15°`。
- 进入 `LandingHover` 时实际终点距离不大于 `0.2 m`，且实际速度满足低速容差。
- 生产配置 setpoint 最大间隔小于 `0.5 s`，不出现零 mask 或地图原点目标。

## 8. 风险和回退条件

- 局部投影窗口太小可能在高速或 odometry 跳变时失去正确段；窗口太大则增加自交跳分支风险。首轮使用基于每周期最大可达移动距离的内部窗口，由自交单元测试约束，不盲目暴露成参数。
- 投影失败时不得使用默认零目标。保持上一个合法 setpoint，并进入可观测的安全暂停/回归处理。
- 若 `trajectory_core` 弧长 API 未通过单元测试，不在应用层复制一套时间采样投影作为长期 fallback，而是停止主链迁移。
- 弧长执行器接入并通过测试后，删除 wall-time 执行逻辑，不通过运行时开关长期保留两套主链。

## 9. 阶段 D 验证结论

- 3 m、8 m 直线、L 型、平滑 S 型与起终点不同的自交路径均完成返航和 AUTO.LAND；名义场景 Rejoin 次数为 `0`。
- 受控 `1.0 m / 1.0 s` 横向 odom 偏差只触发一次 Rejoin，`10.350 s` 后恢复 `ReturnActive`，随后 `24.200 s` 无重触发；终点距离仍为 `0.1949 m`。
- `enable_output_acc=true` 相对 `false` 没有带来稳定的跟踪误差收益，且活动轨迹使用 `type_mask=0`；生产配置保持 `false`。
- 闭合 figure-8 的局部投影没有跳分支，但 `trajectory_core` 生成轨迹在重合端点处存在 yaw 与速度方向近反向的问题。当前应用层不增加闭合路径特判；在轨迹库明确支持前，将此类路线列为禁止实飞的跨仓库残余风险。

详细数值、无效环境尝试和 rosbag 路径见 `doc/当前版本返航飞行测试清单.md` 第 12 节。
