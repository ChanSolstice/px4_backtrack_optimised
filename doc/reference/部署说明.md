# 部署说明

> 适用范围：`feat/return-state-policy` 分支的重构版本（方案 R1–R8）。现在的实飞版本仍是 dev（`b3db1c2`）；重构版本按[实飞测试清单](../testing/实飞测试清单.md)通过台架检查和逐项实飞后再替换 dev。

## 1. 运行环境

| 项 | 要求 |
| --- | --- |
| 机载电脑 | RK3588（arm64），Ubuntu 20.04，ROS Noetic |
| 飞控 | PX4 v1.15.4 改动固件：屏蔽原生 RC 失控保护，CH18 正常 1400、失控 800（方案第 1.4 节）。误刷原生固件时 CH18 为 998 或 1998，模块感知不到失控，状态话题告警 `CH18_UNEXPECTED` |
| MAVROS | 1.x（`ros-noetic-mavros`），本模块用 `/mavros/state`、`/mavros/extended_state`、`/mavros/rc/in`、`/mavros/battery`、`/mavros/setpoint_raw/local` 和 `/mavros/set_mode` |
| 里程计 | `/Odometry_px4`（`nav_msgs/Odometry`，ENU），来自 SLAM |
| 系统包 | `ros-noetic-mavros`、`ros-noetic-mavros-msgs`、`ros-noetic-tf2`、`ros-noetic-visualization-msgs`、`libeigen3-dev`（与 [`scripts/docker/Dockerfile`](../../scripts/docker/Dockerfile) 相同） |

## 2. 代码与版本

工作区中放两个 git 检出（保留 `.git`，构建时要从中取提交号）：

```text
~/Projects/backtrack_ws/src/
├── px4_backtrack_optimised   # 本仓库，要部署的提交
└── trajectory_core           # 固定在 f27f3ad（D13）
```

```bash
cd ~/Projects/backtrack_ws/src
git -C px4_backtrack_optimised checkout <要部署的提交>
git -C trajectory_core fetch && git -C trajectory_core checkout f27f3ad
```

`trajectory_core` 固定在 `origin/dev` 的 `f27f3ad`（D13）：本模块依赖它的弧长查询接口，全部单测、闭环场景和 SITL 都是在这个版本上做的。换版本前要在新版本上重跑这些测试（[单元测试文档](../testing/单元测试文档.md)第 5 节、[闭环仿真与 SITL 测试](../testing/闭环仿真与SITL测试.md)）。

本分支还没有推送到远端时，可以用 `git bundle` 或直接拷贝仓库目录（连同 `.git`）到机载电脑。

## 3. 编译

```bash
cd ~/Projects/backtrack_ws
source /opt/ros/noetic/setup.bash
catkin_make -DCMAKE_BUILD_TYPE=Release --force-cmake
```

- 提交号在 CMake 配置时写入（调试日志 `config` 事件的 `version`）。切换提交后加 `--force-cmake`，否则记录的还是上一次的提交号。
- 可以在板上跑一遍单测：`catkin_make run_tests_px4_backtrack_optimised && catkin_test_results build/test_results`。返航 233 个用例应全部通过（Summary 中的数字是用例数的两倍）。

上实飞前在 RK3588 上测一次规划耗时（方案第 14.2 节）。按 [`scripts/bench/run_gen_bench.sh`](../../scripts/bench/run_gen_bench.sh) 里的 g++ 命令编译 `scripts/bench/gen_bench.cpp`（路径换成工作区的实际路径），运行 `gen_bench <trajectory_config.yaml> 10 30`。本机（x86）10 分钟录制约 0.6 s、30 分钟约 4.8 s；板上的结果应明显小于 `planning_warn_s`（10 s），失控任务的规划在 15 s 悬停内完成。

## 4. 配置

参数在 [`config/backtrack_params.yaml`](../../config/backtrack_params.yaml)，全部必填，代码中没有默认值；`trajectory_core` 的参数在 [`config/trajectory_config.yaml`](../../config/trajectory_config.yaml)，启动时校验。缺少参数或校验不通过时节点打印 FATAL 并退出。参数的含义见文件中的注释和方案第 10 节，不要只改其中一个文件里的同名值。

试飞时打开调试日志：把 `debug_log_enable` 改为 `true`；需要逐拍分析时再把 `debug_log_trace` 改为 `true`（约 30 MB/小时）。日志写到 `debug_log_dir`（现为 `~/Projects/backtrack_ws/debug/`），只保留最近 `debug_log_keep_runs` 个运行目录。

## 5. 启动与检查

```bash
roslaunch px4_backtrack_optimised backtrack.launch
# 同时录原始话题（bag_dir 须已存在）
roslaunch px4_backtrack_optimised backtrack.launch record_bag:=true bag_dir:=$HOME/Projects/backtrack_ws/debug
```

启动日志中应看到 `Publish frequency: 20.0 Hz`、`=== Backtrack Node Initialized ===`，打开调试日志时还有 `Debug log: <运行目录>`（后面带 `(FAILED)` 说明目录建不了）。缺少参数时报 `Required parameter '<名称>' is not set`，配置校验不通过时报 `invalid trajectory_core config`。

每次起飞前（[实飞测试清单](../testing/实飞测试清单.md)第 2 节）：

```bash
rostopic echo -n 1 /px4_backtrack/status
```

- `state` 为 `IdleDisarmed`；
- `alerts` 中没有 `BATTERY_INVALID`、`CH18_UNEXPECTED`、`CH18_UNAVAILABLE`、`FCU_STATE_STALE`、`ODOM_STALE`。电量读数无效时，链路丢失后模块不会因为电量而降落（D11）。

打开调试日志时，`events.jsonl` 第一行的 `version` 应为部署的提交和 `f27f3ad`；为 `unknown` 说明对应的目录不是 git 检出。

## 6. 与航线模块同时运行

航线模块（`px4_mimic_recorder`）和本模块都向 `/mavros/setpoint_raw/local` 发 setpoint，两者之间还没有仲裁（2026-10-10 实飞中航线回放时触发返航，飞机抽搐、往回拽，方案第 16 节）。仲裁节点实施之前，测试返航时不要让航线模块处于回放状态。

## 7. 日志与数据

| 内容 | 位置 | 查看 |
| --- | --- | --- |
| 事件 | `<debug_log_dir>/run_<时间>/events.jsonl` | `python3 scripts/analysis/show_debug_log.py <运行目录> [-t state,control,alert] [-m 任务编号]` |
| 逐拍记录 | 同一目录的 `trace.csv`（`debug_log_trace` 为真时） | PlotJuggler；回放见[系统总览](SYSTEM_OVERVIEW.md)第 8 节 |
| 规划输入和轨迹 | 同一目录的 `plan_<n>_input.csv`、`plan_<n>_trajectory.csv` | `python3 scripts/plot_debug_csv.py --dir <运行目录>` |
| 原始话题 | `<bag_dir>/backtrack_<时间>_<序号>.bag` | `rosbag info`、PlotJuggler |
| 节点输出 | `~/.ros/log/` | 状态转换和告警也打在 rosout |
| 飞控日志 | PX4 的 ULog（SD 卡） | Flight Review、PlotJuggler |

## 8. 更新与回退

- 更新：在两个检出中切到新的提交，按第 3 节编译（带 `--force-cmake`），按第 5 节检查。
- 回退到 dev：`git -C px4_backtrack_optimised checkout dev` 后重新编译。参数文件随代码一起切换（dev 的参数与重构版本不同），不要把重构版本的 YAML 拷到 dev 上用。
