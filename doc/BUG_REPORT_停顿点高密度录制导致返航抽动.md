# Bug Report: 停顿点高密度录制导致返航抽动

| 项目 | 内容 |
| --- | --- |
| 发现日期 | 2026-04-09 |
| 严重程度 | **High** — 返航可完成，但在停顿点附近出现明显抽动 |
| 影响范围 | `TrajectorySession` 输入点构造、停顿点附近的 `ReturnActive` 跟踪 |
| 根因文件 | `src/domain/trajectory_session.cpp`、`config/trajectory_config.yaml` |
| 修复状态 | 已修复，待实飞验证 |

---

## 1. 现象描述

飞行轨迹整体接近直线，但被分为三段：

- 每飞一段后悬停数秒
- 最后通过按钮触发返航

实飞时观察到：

- 无人机整体可以正常返航
- 但在每个“原地停顿”的位置附近出现短促抽动
- 抽动位置与录制阶段的停顿位置基本一致

关联日志片段：

```text
[1775723960.464] Generating trajectory from 580 points
[1775723960.485] Trajectory generated successfully!
[1775723960.485]   Duration: 29.24 s
[1775723960.485]   Path length: 8.57 m
```

关键观察：

1. 路径只有约 `8.57m`，但录制点数达到 `580`
2. 平均点间距约 `0.015m`
3. 对“直线飞行 + 多次停顿”的场景，这意味着停顿期间的微小漂移被大量保留

---

## 2. 根因分析

### 2.1 录制层只按时间节流，不按空间过滤

当前录制缓存 `RecordingBuffer` 只做 `record_max_hz` 的时间节流，不做空间去重：

- 停顿期间如果 odom 持续更新
- 即使无人机只是在原地轻微漂移几厘米
- 这些点也会被完整保留进录制轨迹

这会在停顿位置形成一团高密度点云，而不是单个“停住”的代表点。

### 2.2 `trajectory_core` 默认去重阈值过小

原始配置：

```yaml
min_point_dist_m: 0.01
```

`trajectory_core` 预处理只会合并距离小于 `1cm` 的点。  
但实飞悬停漂移通常在 `2cm ~ 10cm` 量级，因此：

- 停顿期间的大部分点不会被去掉
- 这些点在逆序返航时会变成停顿位置附近的局部折线
- 几何拟合和速度剖面会尝试“认真跟踪”这团局部折线

结果就是返航经过该位置时出现短距离折返、小幅横摆或速度突变，看起来像“抽动”。

### 2.3 当前输入链路缺少“面向返航”的停顿点压缩

`TrajectorySession::generate()` 之前，系统原本直接使用全部录制点逆序构造 waypoint。  
这对“连续运动”路径是合理的，但对“停一下再继续”的任务不够鲁棒：

- 录制侧保留的是原始飞行细节
- 返航轨迹需要的是稳定、低噪声的几何主路径
- 如果不在生成前再做一层抽稀，停顿位置会被过度表达

---

## 3. 故障链

```text
录制阶段：
  直线飞行 -> 停顿数秒 -> 记录到一团高密度悬停点

轨迹生成阶段：
  全量录制点逆序输入 trajectory_core
  -> 停顿处被保留为局部折线/小回环

返航执行阶段：
  无人机经过停顿位置
  -> setpoint 在局部折线之间快速变化
  -> 实际表现为抽动
```

---

## 4. 修复方案

### 4.1 在 `TrajectorySession::generate()` 前增加空间抽稀

文件：`src/domain/trajectory_session.cpp`

新增 `thinRecordedPointsForGeneration()`，在真正调用 `trajectory_core` 前先对录制点做一次“生成前抽稀”：

- 保留首点和末点
- 中间点只有在与上一个保留点的距离大于最小间距时才新增
- 对距离过近的点，用较新的样本覆盖旧样本

这样可以把停顿位置的一团高密度点压缩成更稀疏的代表折线。

### 4.2 抽稀阈值与 `trajectory_core` 几何尺度对齐

当前实现使用：

```cpp
min_spacing_m = max(config.min_point_dist_m, config.ds_m * 0.5)
```

对于当前配置：

- `ds_m = 0.15`
- `min_point_dist_m = 0.05`

因此实际最小抽稀间距为 `0.075m`。

这个量级足以压掉停顿漂移造成的点云团，同时不会明显破坏主路径形状。

### 4.3 调整默认配置

文件：`config/trajectory_config.yaml`

将：

```yaml
min_point_dist_m: 0.01
```

改为：

```yaml
min_point_dist_m: 0.05
```

并增加注释，明确这是为了降低停顿悬停点对返航轨迹的污染。

## 5. 验证方法

### 5.1 单元测试

新增测试：

- `tests/unit/test_trajectory_session.cpp`
- `DensePauseClusterDoesNotBlowUpPathLength`

测试构造“直线 + 停顿点云团 + 直线”的输入，验证生成后的轨迹长度仍接近主路径长度，不会因为停顿点云团而显著膨胀。

### 5.2 实飞 / 联调验证

建议关注以下现象：

1. 轨迹生成日志中是否出现：

```text
Thinned recorded points: N -> M
```

2. 停顿位置附近的返航动作是否明显平顺
3. debug CSV / rviz 中，停顿位置附近是否不再出现密集来回折返

---

## 6. 经验总结

这个问题的本质不是“轨迹库出错”，而是**返航输入没有区分“原始录制细节”和“返航主路径表达”**。

对于“飞一段、停一下、再飞一段”的任务：

- 录制层允许保留足够多的原始点没有问题
- 但轨迹生成前必须再做一层面向返航的空间抽稀

否则停顿期间的微小悬停漂移会被误解释为“需要精确回放的局部机动”，最终体现在返航时的抽动。
