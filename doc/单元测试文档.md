# 单元测试文档

本文档说明 `px4_backtrack_optimised` 当前仓库中已落地的单元测试范围、运行方式、结果判读和后续扩展建议。  
本文以仓库当前 `tests/unit/` 下的 `gtest` 用例为准，不以外部说明或历史文档为准。

## 1. 测试目标

当前单元测试的目标不是覆盖整个 ROS 系统，而是优先验证以下“高价值纯逻辑”：

- 录制缓存的时间戳和节流语义
- 触发器对 `CH7` / `CH18` / RC loss 的判定逻辑
- 返航状态机的关键状态迁移
- 偏离回归策略的最近点搜索与速度限幅
- `trajectory_core` 接入层的轨迹生成、逆序语义和暂停/恢复进度

换句话说，当前测试重点是：

- **先保证领域层和轻集成逻辑正确**
- **暂不把 ROS topic / launch / MAVROS 链路纳入单元测试**

## 2. 测试结构

当前测试目录：

```text
tests/
└── unit/
    ├── test_main.cpp
    ├── test_recording_buffer.cpp
    ├── test_trigger_evaluator.cpp
    ├── test_state_machine.cpp
    ├── test_rejoin_policy.cpp
    ├── test_trajectory_session.cpp
    ├── test_waypoint_fallback_session.cpp
    └── test_backtrack_usecase.cpp
```

说明：

- `test_main.cpp` 提供共享的 `gtest main()` 入口
- 各测试通过 `catkin_add_gtest(...)` 挂到 `CMakeLists.txt`
- 测试目标统一链接 `${PROJECT_NAME}_lib`，尽量复用真实实现而不是复制逻辑

## 3. 当前测试项

### 3.1 `test_recording_buffer.cpp`

覆盖对象：

- `RecordingBuffer`

当前用例：

1. `FirstPointStartsAtZeroTimestamp`
   - 验证首个录制点的相对时间戳为 `0`
2. `ThrottlesHighFrequencySamples`
   - 验证 `record_max_hz` 对高频 odom 点的节流行为
3. `RejectsNonMonotonicTimestamps`
   - 验证时间戳回退或不递增时拒绝录制
4. `ResetClearsRecordedState`
   - 验证 `reset()` 后缓存和时间基准被正确清空

### 3.2 `test_trigger_evaluator.cpp`

覆盖对象：

- `TriggerEvaluator`

当前用例：

1. `Ch7PressEventRequiresStateUpdateAndLongPressTriggersOnce`
   - 验证 `CH7` 按下事件依赖状态机推进，长按仅触发一次
2. `Ch18FailsafeConfirmsAfterConfiguredDurationAndResets`
   - 验证 `CH18` 低电平持续达到确认时间后才触发，并且恢复后可再次触发
3. `RCLossEventHasEdgeSemanticsWhileLevelRemainsLatched`
   - 验证 RC loss 的边沿触发和电平保持语义分离

### 3.3 `test_state_machine.cpp`

覆盖对象：

- `BacktrackStateMachine`

当前用例：

1. `ArmThenStartRecordingTransitionsIntoRecording`
   - 验证 `IdleDisarmed -> WaitRecordDelay -> Recording`
2. `ReturnPreOffboardRequestsOffboardAndEntersReturnActive`
   - 验证 `ReturnPreOffboard` 的预发送计数、`OFFBOARD` 请求和进入 `ReturnActive`
3. `AutoLandHasGlobalPriorityAndYieldsControl`
   - 验证 `AUTO.LAND` 全局优先级与控制权让渡
4. `DirectLandingRequestsAutoLandImmediatelyWhenNotInOffboard`
   - 验证直接降落路径在非 `OFFBOARD` 模式下直接请求 `AUTO.LAND`

### 3.4 `test_rejoin_policy.cpp`

覆盖对象：

- `RejoinPolicy`

当前用例：

1. `TriggerAndExitUseConfiguredDistanceThresholds`
   - 验证偏离触发阈值和回归成功阈值
2. `FindsNearestTimeAndLimitsVelocityForRejoinTarget`
   - 验证最近点搜索、预瞄时间和速度限幅
3. `InvalidTrajectoryReturnsZeroTimeAndDefaultState`
   - 验证空轨迹/无效轨迹输入下的安全返回

### 3.5 `test_trajectory_session.cpp`

覆盖对象：

- `TrajectorySession`

当前用例：

1. `RejectsInsufficientPoints`
   - 验证少于 2 个点时拒绝生成轨迹
2. `MarksTooCloseGeometryFailure`
   - 验证“点过近/起终点几何退化”会被正确分类
3. `MarksInvalidConfigFailure`
   - 验证非法 `trajectory_core` 配置会被显式分类为 `InvalidConfig`
4. `GenerateProducesValidTrajectoryInReverseOrder`
   - 验证轨迹生成成功，且轨迹起点与录制点逆序语义一致
5. `FreezeAndResumeKeepProgressContinuous`
   - 验证暂停/恢复后 `t_progress` 连续
6. `DensePauseClusterDoesNotBlowUpPathLength`
   - 验证高密度停顿点云团不会把返航路径长度明显拉爆
7. `SetProgressControlsFinishedState`
   - 验证手动设置进度后完成态与 `reset()` 行为

### 3.6 `test_waypoint_fallback_session.cpp`

覆盖对象：

- `WaypointFallbackSession`

当前用例：

1. `BuildCreatesReverseSparsePath`
   - 验证退化返航会按逆序构建稀疏 waypoint 路径
2. `ProgressAdvancesAndCanRestartFromHead`
   - 验证退化路径可推进，且暂停恢复时可从头 restart
3. `ProgressAdvancesAtMostOneWaypointPerTick`
   - 验证单个 tick 最多推进一个 waypoint，避免重叠到达半径导致跳点
4. `FinalWaypointMarksSessionFinished`
   - 验证最后一个 waypoint 到达后会话完成

### 3.7 `test_backtrack_usecase.cpp`

覆盖对象：

- `BacktrackUseCase`

当前用例：

1. `FallsBackToImmediateLandingWhenTrajectoryGenerationFails`
   - 验证原地悬停点过近场景会直接降级为原地降落
2. `DoesNotFallbackWhenTrajectoryConfigurationIsInvalid`
   - 验证非法轨迹配置不会误切到 waypoint fallback，而是停留在 `ReturnPreOffboard`

## 4. 覆盖边界

当前测试**已覆盖**：

- 领域层核心行为
- `trajectory_core` 接入层的关键语义
- 状态机关键主路径

当前测试**未覆盖**：

- ROS subscribers / publishers / services 适配层
- launch 参数装配与节点启动链路
- debug CSV 导出与 rviz 可视化发布
- 与 PX4 / MAVROS 的真实联调

因此，当前结论应理解为：

- **核心逻辑已有基础回归保护**
- **系统级行为仍需编译验证和联调验证**

## 5. 运行方式

在 catkin 工作空间根目录执行：

```bash
catkin_make --pkg trajectory_core px4_backtrack_optimised
catkin_make run_tests_px4_backtrack_optimised
catkin_test_results
```

也可以手动执行单个测试二进制：

```bash
./devel/lib/px4_backtrack_optimised/test_recording_buffer
./devel/lib/px4_backtrack_optimised/test_trigger_evaluator
./devel/lib/px4_backtrack_optimised/test_state_machine
./devel/lib/px4_backtrack_optimised/test_rejoin_policy
./devel/lib/px4_backtrack_optimised/test_trajectory_session
./devel/lib/px4_backtrack_optimised/test_waypoint_fallback_session
./devel/lib/px4_backtrack_optimised/test_backtrack_usecase
```

## 6. 结果判读说明

运行测试时，部分用例会打印 `ROS_INFO` / `ROS_WARN` 日志，这不一定表示失败。

典型情况：

- `TrajectorySessionTest.RejectsInsufficientPoints`
  - 会打印“点数不足”的错误日志
  - 这是用例故意验证的失败路径，**属于预期行为**
- `TrajectorySession` 相关测试可能打印 `Timestamp fallback`
  - 这是因为测试数据故意包含较大时间间隔，用于验证新版 `trajectory_core` 时间质量诊断链路
  - 只要测试断言通过，**该 warning 属于预期行为**

判定测试是否通过，应以：

- `gtest` 用例统计
- `catkin_test_results` 汇总结果

为准，而不是只看日志级别。

## 7. 当前测试原则

当前测试编写遵循以下原则：

1. 优先测纯逻辑，不优先测 ROS topic
2. 优先测边界条件、状态迁移和语义容易踩坑的地方
3. 尽量复用真实实现，不造一套平行逻辑
4. 浮点比较优先使用 `EXPECT_NEAR(...)`，避免二进制浮点误差导致伪失败

## 8. 后续建议

建议后续按以下顺序扩展：

1. 继续补 `BacktrackUseCase` 轻集成测试
   - 重点覆盖“可恢复生成失败 => waypoint fallback return / pause-resume / LandingHover 收尾”
2. 补 debug 导出相关测试
   - CSV 文件名、字段和导出时机
3. 补 adapters 层测试
   - 主要验证消息映射和线程安全边界
4. 视需要补 `rostest`
   - 验证 launch 参数、topic 连线和节点级行为
